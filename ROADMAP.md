# Learning Roadmap
A sample implementation is not proof of mastery. Complete the exit task before marking a topic learned.

## 1. Java OOP
Classes, constructors, access modifiers, encapsulation, inheritance, overriding, runtime polymorphism, abstract classes, interfaces, composition, equals/hashCode, and SOLID basics.
Exit task: model a library or inventory domain with interfaces, validation, and composition.

## 2. Java Collections
ArrayList, LinkedList, ArrayDeque, HashMap, HashSet, TreeMap, TreeSet, PriorityQueue, Comparable, Comparator, hashing contract, ordering, iterator behavior, and complexity trade-offs.
Exit task: implement word frequency, deduplication, and top-K frequency queries.

## 3. Java Multithreading
Thread lifecycle, Runnable, Callable, ExecutorService, race conditions, visibility, atomicity, synchronized, volatile limitations, ReentrantLock, atomics, concurrent collections, futures, deadlocks, interruption, and graceful shutdown.
Exit task: build a bounded producer-consumer pipeline and test concurrent counter correctness.

## 4. C++ STL
vector, array, deque, list, map, set, unordered_map, unordered_set, stack, queue, priority_queue, iterators, sort, lower_bound, upper_bound, binary_search, accumulate, and iterator invalidation.
Exit task: solve frequency, top-K, sorting, and interval tasks using STL idioms.

## 5. DSA
Complete the 30 problems in both languages. Explain invariants and complexity; test empty, singleton, duplicate, negative, boundary, and large inputs. Then expand into heaps, trees, graphs, greedy, dynamic programming, tries, and advanced graph algorithms. Thirty problems are a starting set, not a complete interview-preparation target.

## 6. Advanced engineering
C++ ownership, RAII, stack/heap lifetime, pointers/references, copy/move semantics, unique_ptr/shared_ptr/weak_ptr, exception safety, Rule of Zero. Learn Strategy, Factory Method, Observer, Adapter, Decorator, and Builder as tools for real design problems, not patterns to apply mechanically.

## Weekly cadence
Four sessions DSA; two sessions language fundamentals/code review; one session revision, testing, documentation, and design practice. Track attempted problems, hints, mistakes, and review dates.
